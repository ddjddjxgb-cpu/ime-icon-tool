# 设计文档

> 目标读者：本项目使用者，以及想了解「为什么这样设计」的开发者。

---

## 0. 一个必须先讲清的前提

本程序是**本机系统工具**：它修改 `HKEY_LOCAL_MACHINE` 下某个输入法剖面的
`IconFile` 值，让 Windows 任务栏的输入指示器读取我们指定的图标文件。

**这类程序没有"账号"这个维度。** 它的权限边界是：

```
Windows 登录会话  →  UAC 提权  →  HKLM 写入
```

因此有一项常见需求被**明确拒绝实现**：

| 需求 | 处理 | 理由 |
|---|---|---|
| 应用层身份认证 | ❌ **不做** | 见第 5.1 节，加了只有坏处 |

---

## 1. 目标用户

### 1.1 主要群体：想改输入法图标的普通用户

| 维度 | 描述 |
|---|---|
| 系统 | Windows 10 / 11，64 位 |
| 输入法 | 第三方中文输入法或系统自带输入法 |
| 技术水平 | **会下载并双击运行；不知道注册表是什么** |
| 痛点 | 任务栏输入指示器图标难看／与系统风格不搭／想换成正楷字 |
| 期望 | 点几下就好；随时能还原；不要搞坏系统 |
| 语言 | 简体中文 |

### 1.2 次要群体：多输入法用户

装了 2～3 个输入法，希望每个的图标换成不同的字以便一眼区分
（例如「中」「五」「拼」）。

### 1.3 明确不面向

- 企业批量部署管理员（需要 MSI / 组策略 / 代码签名，超出本工具范围）
- 期望云端管理、多设备同步的用户（本工具纯本地，无网络）
- 想改**键盘布局**图标的用户（那是另一套注册表位置，本工具不覆盖）

## 2. 核心使用场景

| # | 场景 | 触发 | 成功标准 |
|---|---|---|---|
| S1 | **首次替换**（主场景） | 嫌默认图标难看 | 任务栏出现用户选定的字，且随时可还原 |
| S2 | **改字** | 想换成另一个字或字重 | 图标更新为新字 |
| S3 | **还原** | 换错了／不想用了 | 完全恢复成原始图标（值 + 类型都一致） |
| S4 | **查看现状** | 不记得自己改没改过 | 明确显示当前图标来源 |
| S5 | **多输入法分别设置** | 装了多个输入法 | 每个输入法可独立设置 |

**非目标场景**：批量部署、跨设备同步、改系统主题、改候选框样式。

## 3. 关键功能

| 功能 | 说明 | 优先级 |
|---|---|---|
| 输入法自动发现 | 枚举本机所有声明了 `IconFile` 的 TSF 剖面 | P0 |
| 自定义字符 | 用户输入**一个**字符作为图标 | P0 |
| 字体 / 字重 / 字号 | 从**系统已装字体白名单**中选；字号比例可滑动 | P0 |
| 实时预览 | 按 16/20/24/32px 预览，可切浅色/深色背景 | P0 |
| 应用 | 生成图标宿主 → 校验 → 备份 → 写注册表 | P0 |
| 一键还原 | 用备份的原值（含值类型）写回 | P0 |
| 备份导出 | 备份可存成文件，重装后可恢复 | P1 |
| 刷新提示 | 说明刷新方式，提供「刷新图标」按钮 | P1 |
| 诊断日志 | 可复制的纯文本，含环境信息与每步结果 | P1 |

### 明确不做的功能

- 联网下载图标或字体（引入供应链风险，且非必需）
- 自动更新（同上）
- 开机自启／托盘常驻（用户不需要一个常驻程序）
- 遥测与使用统计
- 修改除 `IconFile` 外的任何注册表值

## 4. 界面设计

### 4.1 三步向导（而非一屏堆满按钮）

```
┌─ ① 选择输入法 ── ② 设计图标 ── ③ 应用 ─┐
│   [内容区随步骤切换]                    │
│   [上一步]                    [下一步]  │
└────────────────────────────────────────┘
```

**为什么用向导**：一屏塞进状态、多个按钮、单选组和日志，对新用户是认知负担。
向导把「先做什么」变成界面结构本身。

### 4.2 可访问性

| 项 | 措施 |
|---|---|
| 键盘 | 全流程可仅用 Tab / Shift+Tab / Enter 完成 |
| 色彩 | **不靠颜色单独传达信息**（"成功"同时有文字，不只靠绿色）|
| 对比度 | 正文 `#1a1a1a` on `#f3f3f3`，约 13:1（远超 WCAG AA 的 4.5:1）|
| DPI | 声明 DPI 感知；在 100%～250% 缩放下按逻辑像素布局 |
| 字号 | 不硬编码像素；跟随系统 |
| 动效 | 无闪烁动画；无自动消失的提示（避免来不及读）|
| 窗口 | 允许调整大小；尺寸限制在屏幕逻辑范围内 |

### 4.3 错误提示格式（三段式）

不只说"失败了"：

```
【出了什么错】写注册表被拒绝（错误 5：访问被拒绝）
【为什么】    这一步需要管理员权限，当前不是管理员
【怎么办】    在 UAC 弹窗里选「是」，或重试
```

## 5. 安全设计

### 5.1 为什么不做应用层身份认证（重点）

**结论：拒绝实现。** 理由：

1. **它不提高任何安全门槛。** 本工具的全部能力上限是「以当前用户身份改一个
   注册表值」。攻击者若已能运行任意程序于该用户会话，他**直接改注册表即可**，
   不需要绕道本工具。加登录框只是把"能改注册表"变成"能改注册表 + 知道一个
   密码"，攻击面没变。

2. **它会制造虚假安全感。** 用户看到"已登录"，会以为改动受保护。实际上没有
   任何保护。这比没有登录框更危险 —— 它误导用户做出错误的风险判断。

3. **它引入新的真实风险。** 要有登录就得存凭据，就得决定存哪、怎么加密。
   在纯本地工具里这是**凭空造出一个可被攻击的秘密**。原来根本没有这个资产。

4. **它损害易用性且无补偿。** 每次改图标都要登录，是纯粹的成本。

**那"认证"在本地工具里的真实等价物是什么？**

| 常见误解 | 真实等价控制 |
|---|---|
| 应用层账号密码 | **Windows 用户账户 + UAC** —— 系统已经做了，且更可靠 |
| 应用层角色权限 | **最小权限原则**：只在必须的那一步提权 |
| 会话令牌 | **无会话**：每次操作独立，失败即中止，无持久状态可劫持 |

### 5.2 权限控制

| 控制 | 实现 |
|---|---|
| **最小权限** | 生成图标、预览、备份、诊断 —— **全部免提权**。只有"写注册表"提权 |
| **禁止静默提权** | 提权前必须弹出说明，写清"要改什么、为什么、怎么撤销" |
| **提权动作最小化** | 提权后只做一次**固定形态**的注册表写入，**不执行任何 shell 命令** |
| **路径收敛** | 见 5.3 —— 最关键的一条 |

### 5.3 路径收敛 —— 本项目最重要的一条安全控制

**风险**：本工具的能力是"把某个输入法的图标来源指向一个 DLL"。
如果它接受**任意路径**，就等价于一个通用的
「让高权限进程去加载攻击者指定 DLL」的工具 —— 这是典型的**提权/持久化原语**。

**控制**：

1. 应用**只**会写入指向**自己数据目录**内的路径（`%LOCALAPPDATA%\ImeIconTool\`）。
2. 写入前逐项校验该路径：
   - 必须是绝对路径
   - 必须解析后仍位于应用数据目录之内（防 `..` 穿越、防符号链接逃逸）
   - 文件必须存在
   - 必须是 **x64 PE**，且**恰好含 1 个 `RT_GROUP_ICON`**、`ExtractIconExW(-1)` 返回 1
3. 用户**无法**通过界面输入任意路径（路径由程序构造，不是用户输入）。
4. 拒绝写入指向系统目录、Program Files 或其它任意位置的 `IconFile`。

**代价**：用户不能把图标指向自己的任意文件。对真实需求无影响
（没人需要这么做），对滥用场景是硬阻断。

### 5.4 数据保护

| 项 | 做法 |
|---|---|
| 不收集任何个人信息 | 无账号、无设备指纹、无使用统计 |
| 不联网 | 程序**不含任何网络代码**。可断网使用 |
| 不写日志到系统目录 | 日志只存应用数据目录，用户可自行查看与删除 |
| 备份含原值与原类型 | 备份记录 `IconFile` 的**值 + 数据类型**。写错类型会破坏输入法 |
| 备份可导出 | 导出为 JSON，重装系统后仍可恢复 |
| 卸载即净 | 删除数据目录 + 一键还原注册表；不残留 |

> 注意：本工具处理的"数据"不含个人隐私。真正的数据保护重点是
> **不把系统原有配置弄丢**（备份 + 类型保真）和**不引入网络泄露面**。

### 5.5 输入校验

| 输入项 | 规则 | 拒绝时提示 |
|---|---|---|
| 字符 | 恰好 1 个字符；拒绝控制字符、路径分隔符 `\ / : * ? " < > \|`、空白 | "只能输入 1 个字符" |
| 字体 | 只能从**枚举出的系统已装字体白名单**中选 | 下拉框本身就是约束 |
| 字重 / 字号比例 | 固定枚举值 | 控件本身就是约束 |
| 目标输入法 | 只能从**注册表枚举结果**中选 | 列表本身就是约束 |
| 生成的文件 | 写入前做 PE 结构校验 | "生成的图标文件校验未通过，已中止" |

**任何一项校验失败 → 中止，不写入任何东西。** 不做"尽力而为"的部分写入。

### 5.6 防滥用

| 滥用形态 | 阻断手段 |
|---|---|
| 当作「DLL 重定向器」用 | 路径收敛（5.3）—— 最核心 |
| 静默提权后做别的事 | 提权动作是固定的一次注册表写入，无 shell、无参数拼装 |
| 反复写入骚扰 | 写入前先比较目标值，值相同则跳过（幂等）|
| 冒充官方程序 | 见 5.7 —— 诚实说明未签名 |
| 用户被误导点"是" | 提权前弹窗逐条列出将要发生的改动与撤销方式 |

### 5.7 分发信任（诚实说明的限制）

| 现实 | 说明 |
|---|---|
| **没有代码签名证书** | 首次运行会看到 SmartScreen 蓝色警告。这是未签名程序的**正常**表现 |
| 给用户的指引 | 说明会看到什么警告、为什么，以及如何核对来源可信 |
| 不做的补救 | **不会**教用户关闭 SmartScreen 或加白名单 —— 那会削弱系统整体安全 |
| 长期方案 | 若要正经分发，需购买代码签名证书（OV/EV）并签名 |

**这一条本身就是"安全 vs 易用"的取舍**：签名能让用户顺畅运行，
但证书要花钱、要走身份审核；不签名则每个用户都要多过一道心理关。

## 6. 安全性与易用性的取舍（逐条）

| 取舍 | 选择 | 安全收益 | 易用代价 |
|---|---|---|---|
| 路径是否可自定义 | **限定在应用目录** | 阻断"通用 DLL 重定向"滥用 | 不能指向任意位置（真实需求不需要）|
| 何时提权 | **只在写注册表时** | 最小权限；误操作面最小 | 每次应用/还原都过一次 UAC |
| 是否强杀 explorer 刷新 | **不杀**，只重启 ctfmon | 避免桌面整体消失的风险 | 用户可能需自己注销重登 |
| 是否做应用层登录 | **不做** | 不制造虚假安全感；不新增凭据资产 | 无"账号"体验（本就不需要）|
| 字符是否允许多个 | **只允许 1 个** | 避免小尺寸糊成一团 | 不能写"输入法"三个字 |
| 字体是否自由指定 | **白名单** | 不加载任意字体文件 | 只能用已装字体 |
| 是否联网获取素材 | **不联网** | 无供应链攻击面 | 素材需自带 |
| 错误时是否"尽力而为" | **全中止** | 不留半改状态 | 偶发失败需整步重做 |
| 是否自动更新 | **不自动** | 无更新通道被劫持的风险 | 用户需自行换新版 |
| 备份是否强制 | **强制且不可跳过** | 永远可回滚 | 占少量磁盘 |

## 7. 验收标准（可客观检验）

1. 在**未安装特定输入法**的机器上，能正确列出该机器上的输入法并完成替换。
2. 输入 `..\..\Windows\System32\evil.dll` 之类的字符或路径时被拒绝，
   且**不产生任何写入**。
3. 还原后，注册表的 `IconFile` **值与类型**与改动前完全一致。
4. 卸载数据目录后，程序能自动重建所需文件（自恢复）。
5. 全流程可仅用键盘完成。
6. 断网环境下功能完全不受影响。
7. 任何一步失败后，系统状态与操作前一致（无半改状态）。

这些标准由 `tests/test_security.py` 与 `tests/smoke_test.py` 覆盖。
